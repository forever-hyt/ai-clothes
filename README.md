# 衣搭灵感 · 安全演示

真实 AI 与支付尚未接入。数据库与注册（Supabase Auth）的代码路径已实现，但需配置密钥并执行数据库迁移后才可用；默认仍是内存演示（见“APP_MODE 与 Supabase 数据库”一节）。

## 工作台与语言

顶部“创作工作台”和“隐私与安全”是独立切换按钮，手机端同样可见。页面内切换保留当前素材，并支持浏览器返回。简体中文 / English 切换覆盖导航、工作台、隐私、条款、登录及错误提示；只在浏览器保存语言偏好。

工作台按“图片上传 / 参数配置 / 生成任务 / 生成结果”四区组织，右上角重新生成按钮与结果区保留。登录后走服务器演示生成：参数区显示预计消耗、可用余额、冻结中额度与演示流水；提交时服务器按消耗冻结（余额不足整体回滚），结果可下载后才结算，失败、取消或超时自动退还。任务区提供“模拟一次失败”演示开关、四段进度、演示幂等键与活动期取消按钮；断网或刷新后自动按幂等键查找并恢复进行中的任务。保存作品是服务器内存里的演示标记，随保留期（约 30 分钟）清除。

演示 Credits 是内存账本：重启即重置，不涉及真实资金，界面与接口（`simulated: true`）均明确标注。未登录仍可本地预览，不消耗也不接触服务器配额。

本地演示无需登录：仅使用内置成年人物插画与内置衣橱素材，单独确认本地处理授权及成年、非色情用途后可制作搭配板、查看原图并下载 PNG。自上传素材仅本地查看，审核未接入前禁止生成与导出。图片仅在浏览器处理，搭配板不是 AI 换装结果。真实衣服替换入口关闭。服务器演示生成同样仅使用内置素材（不包含你的照片），因内容审核未配置拒绝任何上传图生成。

## 配置登录账号

运行 `npm run setup-login`，在本机输入用户名和密码（密码隐藏，至少 12 位）。脚本仅将用户名和加盐密码哈希写入已被 Git 忽略的 `.env.local`，不会保存明文密码，并保留其他环境配置。配置后重启本地服务。不要将密码发送到聊天或提交到仓库。

公网部署需要将 `LOGIN_USERNAME` 与 `LOGIN_PASSWORD_HASH` 配置到平台服务器环境变量，并设置正确的 HTTPS `APP_ORIGIN` 后重新部署。未配置账号时，页面明确说明登录尚未开放；本地演示继续可用。登录后客户端会验证会话，Cookie 未保存时显示说明。

检查：`npm run test`、`npm run lint`、`npx tsc --noEmit --incremental false`。

## 服务器配置

部署平台服务器环境变量：LOGIN_USERNAME、LOGIN_PASSWORD_HASH、APP_ORIGIN（HTTPS 网站完整来源，无末尾斜杠）、PRIVACY_CONTACT（公开展示的联系方式）。未设置账号或有效哈希时拒绝登录，旧测试密码已停用。数据库模式另需 NEXT_PUBLIC_SUPABASE_URL、NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY（公开）与 SUPABASE_SERVICE_ROLE_KEY（仅服务端）及 APP_MODE（见下一节）。

哈希格式：16 字节盐的十六进制字符串 + 冒号 + 64 字节 scrypt 哈希的十六进制字符串，使用 Node scrypt 默认参数。离线生成，勿把明文密码写进源码、命令历史或日志。

AI、数据库、支付密钥只放服务器环境变量。禁止 NEXT_PUBLIC_ 前缀、硬编码进页面/public、提交 Git、写日志或返回浏览器。当前未调用任何 AI 服务商。

运行 npm install、npm run dev。本地 APP_ORIGIN=http://localhost:3000。生产 npm run build 后 npm start；配置 HTTPS。生产 Cookie 强制 Secure、HttpOnly、SameSite=Strict。

## APP_MODE 与 Supabase 数据库（生产路径）

`APP_MODE` 显式切换运行模式：不设置或 `demo` → 内存演示（默认）；`production` → Supabase Auth + PostgreSQL 事务账本/任务。

- **production 的硬性前提**：`APP_MODE=production` + 三个 Supabase 配置（URL、publishable key 公开；service_role key 仅服务端）全部为真实值，且已执行 `docs/supabase-schema.sql` 迁移。任一条不满足都不会回退 demo：配置缺失或模式值非法 → 接口一律 503 `CONFIG_ERROR`；数据库不可用（含迁移未执行）→ 503 `DB_UNAVAILABLE`。
- **注册 / 登录 / 退出**：浏览器经 Supabase Auth 直接完成；服务端每个请求用 `auth.getUser()` 校验身份，「未登录」与「数据库不可达」严格区分（401 与 503 不混用）。
- **账本边界**：所有 Credits 冻结/结算/释放与任务事务都在服务端经 service_role（SQL 中 SECURITY DEFINER 函数的唯一授权角色）完成，客户端 anon/authenticated 对账本零写权限；浏览器本地余额永远只是显示。
- **心跳 / 租约**：活动任务每 10 秒刷新 `updated_at` 租约；对账超时阈值（默认 60 秒，6 个心跳）即租约期限——进程崩溃或热重载丢失定时器后心跳停止，租约过期由对账回收并退还冻结。结算结果先缓存、随心跳重试，失败不会误收未完成任务的费用。
- **迁移未执行前的状态**：`production` 模式下登录可用（身份校验不依赖数据库表），但 Credits 与任务接口返回 503 并明确提示「尚未完成初始化」——不会声称真实存储已可用。演示 Credits 标签与 `simulated: true` 字段在所有模式下保留，不接入真实支付。
- **SQL 可重复执行**：`docs/supabase-schema.sql`（v2.2）采用 if-not-exists / OR REPLACE / 先撤销再授权，可安全重跑，不覆盖数据、策略或权限；文件末尾内置**自动化结构自检**（表/列/约束/RLS/策略/函数授权逐项断言，失败即整体回滚），并配套真实 PostgreSQL 集成测试（`docs/supabase-integration-tests.sql`）与迁移前检查清单（`docs/migration-checklist.md`）。

## 保护措施

内置样例确认授权与非色情用途才可制作搭配板；真实换装关闭，服务器审核未配置即拒绝输出；同源校验；登录与接口限流；单次并发处理；5MB / 2000 万像素限制；真实 JPEG/PNG/WebP 解码重编码清除元数据；拒绝动画。图片只在请求内存处理，不落盘、不发送第三方。页面下载、手动清除及每 30 分钟自动清理。隐私和条款入口，基础安全响应头。

演示计费的安全语义：浏览器本地余额永远只是显示，不是账本；冻结、结算、释放全部由服务器在互斥临界区内串行执行；先冻结后生成、结果可下载后才结算、失败/取消/超时自动释放；同一提交的幂等键防重复扣费，超时与断线先查任务再决定重发；后台对账循环回收超时任务、过期结果与孤儿冻结。以上是演示版的单进程语义，生产环境必须替换为数据库事务与独立对账任务（见 docs/credits-system.md）。

## 公网部署边界

demo 模式适合单进程、授权账号的受限演示：会话、演示 Credits 与生成任务都存在内存，重启重置，多实例不共享，切勿把 Credits 当真实计费。production 模式的代码路径（Supabase Auth、PostgreSQL 事务账本/任务、心跳租约）已实现，但正式启用前必须先执行 docs/supabase-schema.sql 迁移并配置密钥——迁移未执行时 production 接口返回 503，不会静默退化。多实例生产部署还需把对账改为 pg_cron 调度（SQL 注释已附）。正式 SaaS 仍缺：边缘请求限流及超时、真实运营方联系方式。AI 接入需先确认服务商及隐私规则。不落盘方案无需图片存储清理任务。

这些修改必须重新部署并重启公网服务才生效。旧默认账号需立即停用。若密钥曾进入 Git、前端产物或日志，必须在供应商处撤销/轮换；删除源码不能让泄露密钥失效。代理、APM 和托管日志不要保存请求体、Cookie 或图片。本地检查不等于公网服务器审计。

## 内容安全与隐私边界（2026-10-04）

服装图片不能为空。浏览器与服务器使用透明度合成后的像素方差拦截疑似纯色、全透明或近乎空白图；此项不是衣物识别或色情检测，低对比度照片可能误判。无服装或上传失败时移除旧服装并清空结果、授权，防止继续用旧素材运行。更换任一素材后需重新授权。

色情、裸露、脱衣、性化换脸、性骚扰、未成年人照片和未经授权肖像用途被禁止。当前没有内容审核服务，也没有真实换装模型；未审核上传素材不能生成/导出，后端不会信任客户端的 reviewed/approved/builtin 标记。不得仅通过增加环境变量或移除拦截开放换装；必须实现输入、输出审核及错误时停止生成。

自上传图在本地重编码以清除源 EXIF/GPS。撤回同意、手动清除、退出账号或每 30 分钟清除素材和预览。用户下载副本不受页面清除控制。图片、请求体、Cookie 不应进入托管/APM 日志；还需在实际部署环境核验。未来 AI 图片应保留所需显式及隐式生成标识，不能沿用源元数据清理作为删除生成标识的理由。

隐私和条款页面附官方法律法规参考，说明个人信息权益、肖像授权、投诉机制和第三方处理边界。当前缺少运营方公开身份、有效隐私联系方式和投诉提交系统，不能宣称全面合规。当前成年声明不是自动年龄核验。不得接收未成年人照片。
